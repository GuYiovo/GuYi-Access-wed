系统要求与部署

GuYi Access Pro v2026.10.6 后端基于原生 PHP 构建，运行负载较轻，满足基本要求的 Web 环境即可部署。

  • PHP 版本：建议使用 7.2 或更高版本（必须启用 PDO 和 JSON 扩展）
  • 数据库：MySQL 5.6 或更高版本

快速部署步骤：

将源码上传到网站根目录，然后访问 http://你的域名/install.php。按照页面提示填写数据库连接信息并点击安装，系统将自动创建所需的数据表。

通信协议与全局请求频率限制

当前服务端提供统一的 JSON API 供客户端验证。请向应用管理后台提供的真实 PHP API 地址发送 HTTPS POST 请求；不要默认静态官网域名就是 API 域名。

POST /Verifyfile/api.php
Content-Type: application/json

服务端按 IP 地址限制请求频率，超出限制时会返回 HTTP 429 和 JSON 错误。客户端应设置连接与读取超时，并在收到频率限制响应后稍后重试。请避免频繁轮询。

卡密验证（以当前服务端源码为准）

当前版本的 Verify.php 不会校验旧版 timestamp 和 sign 字段。基础验证使用 app_key 和 card_code，同时建议提供稳定的 device_hash。请勿照搬旧版签名算法示例。

请求参数

参数类型是否必填说明
app_key字符串必填在管理后台创建应用时生成的 64 位十六进制 AppKey。当前加密实现会将其解码为 32 字节的 AES 密钥。
card_code字符串验证时必填用户输入的授权卡密。如果省略此参数，API 将返回应用更新信息和公开云变量，而不会执行卡密验证。
device_hash字符串建议填写当前安装环境的稳定设备标识。服务端会将卡密绑定到该字符串。如果省略此参数，则会使用请求来源 IP 的 MD5 哈希值作为备用标识；网络变化时可能导致绑定不稳定。
custom_data字符串选填与卡密关联的自定义文本。如需存储 JSON，请先将其序列化为字符串再发送。
action字符串选填默认操作为卡密验证，可以省略此字段。只有在服务端明确实现了相应管理操作时，才使用其他 action。

重要提示：当前服务端的客户端访问限制

当前的 Database::verifyCard() 会检查 HTTP User-Agent。只有其中包含 [IOS_WEBAPP_VERIFIED]，或该卡密已设置 browser_whitelist=1 时，验证才会继续。下方通用 SDK 示例不会伪造此标记。对于普通桌面端或移动端客户端，请根据自身策略启用对应卡密的浏览器白名单，或调整服务端客户端授权逻辑，否则请求将被拒绝。

响应格式与成功判断

成功解密后的响应结构为 {code, msg, data}。data 对象可能包含 expire_time、custom_data、update 和 variables。请通过 JSON 字段 code === 200 判断业务是否成功。部分错误响应为未加密的 JSON，因此不要假设每个响应都包含 encrypted_data。

活跃设备与心跳更新

当前源码没有单独实现 action=heartbeat 分支。已绑定设备再次提交相同的应用密钥和 device_hash 时，服务端会刷新该活跃设备的 last_heartbeat。请勿将旧版 action=heartbeat 当作独立接口。轮询时应保持合理间隔，并遵守单 IP 请求频率限制。

设备自助解绑

用户更换电脑时可以自行解绑设备。系统会扣除指定的惩罚时长，以减少人工客服处理需求。

  • 参数： action=unbind, card_code=TARGET_CARD_CODE
  • 惩罚时长： 成功调用此接口后，卡密剩余有效期将扣除 12 小时。
  • 工作方式： 调用成功后，系统会清除该卡密的设备记录。用户在新电脑上登录并验证卡密时，新设备将自动完成绑定。

软件更新与云变量

提供有效的 app_key 但不提供 card_code 时，API 会返回应用更新信息和公开云变量。卡密验证成功后，响应中的 data 对象也可能包含卡密到期时间、自定义数据、更新信息和应用变量。

custom_data 是与卡密关联的自定义字符串，并非独立的变量接口。发送对象前，请先将其序列化为 JSON 文本。不要将嵌入客户端或云变量中的 AppKey 视为无法提取的秘密。

自动化卡密分发平台与管理 API

这些接口用于自动化卡密分发平台和机器人管理。请求必须携带 api_token 进行身份验证。

安全警告：当前仓库中包含硬编码的默认管理 API 令牌。部署前，请将其替换为高强度随机令牌，并通过安全配置或环境变量加载。切勿将管理令牌写入客户端应用或公开文档。

1. 批量生成卡密（用于分发平台）

  • 参数： action=generate, api_token=YOUR_TOKEN, app_id=YOUR_APP_ID, type=day 或 type=custom, num=COUNT
  • 可选参数： pre=PREFIX, note=NOTE, custom_hours=HOURS （与 type=custom 搭配使用）
  • 响应： 响应中包含 card_string 字段，其中的卡密以换行符分隔，可直接导入分发平台。

2. 强制下线并解绑（不扣除时长）

  • 参数： action=kick, api_token=YOUR_TOKEN, card_code=TARGET_CARD_CODE
  • 用途： 管理员可以强制清除目标卡密的设备绑定，且不会扣除任何惩罚时长。

3. 封禁、解封与永久删除

  • 加入黑名单： action=ban （暂停该卡密，并阻止用户登录）
  • 解除封禁： action=unban （恢复正常状态）
  • 永久删除： action=del_card （从数据库中永久删除该卡密）

主动防御与云端黑名单（高风险操作）

此接口用于增强软件防护。当客户端检测到用户环境中存在 CE / OD、抓包工具或内存注入 等情况时，可以调用此 API，将相关设备加入云端黑名单。

严格执行：触发后，相关设备的 device_hash 和公网 IP 地址将被加入云端黑名单，后续访问会被拦截。
  • 操作： action=ban_machine（或 action=blacklist）
  • 必填参数： device_hash=TARGET_DEVICE_HWID
  • 可选参数： reason=REASON

AES-256-GCM 响应解密

在管理后台启用 API 加密，并且服务端在构建响应时获得有效 AppKey 后，外层响应将包含 encrypted_data。请先对该值进行 Base64 解码，再按照服务端使用的顺序拆分数据。

{ "encrypted_data": "Base64(IV + Tag + Ciphertext)" }
  • 密钥： 当前服务端会将 64 位十六进制 app_key 解码为 32 字节 AES-256 密钥，不会使用 api_secret。
  • 前 12 字节： IV（初始化向量）。
  • 接下来的 16 字节： GCM Tag（认证标签）。
  • 剩余字节： 密文。部分编程语言的加密库要求认证标签位于密文之后，因此示例会根据各语言库的要求重新排列数据缓冲区。
  • 身份验证： 务必验证 GCM Tag。如果解密或身份验证失败，应拒绝该响应并停止后续处理。
  • 错误响应处理： 当前部分错误处理路径在没有 AppKey 的情况下构建响应，因此会返回 {code, msg, data} 格式的明文 JSON。客户端必须同时支持这两种响应格式。

安全说明： AppKey 同时承担客户端可见标识和对称解密密钥的作用。如果将其嵌入桌面端或移动端应用，可能通过逆向分析提取；代码混淆无法保证其绝对保密。切勿将管理用的 api_token 放入客户端。

8 种编程语言的客户端接入示例

以下示例与当前仓库中的请求字段、响应结构和 AES-GCM 字节布局保持一致。请替换 API 地址、AppKey、卡密和稳定设备标识，然后安装对应编程语言所需的依赖。

请先阅读上方的“客户端访问限制”。当前服务端可能要求启用卡密的浏览器白名单；否则，即使通用 SDK 的请求格式正确，也可能被拒绝。

全局状态代码

业务代码含义建议的客户端处理方式
200验证或请求成功仅当解密和解析均完成，且业务代码为 200 时，才继续执行。
400缺少必填参数、未提供卡密，或 action 参数无效检查必填字段和参数名称。
403AppKey 错误、应用不可用、卡密无效或已被封禁、设备与现有绑定冲突，或触发了客户端策略显示服务端返回的 msg 并拒绝访问。不要将错误响应当作成功。
404部分管理操作指定的卡密记录不存在检查目标卡密和应用。
429超出单 IP 请求频率限制降低请求频率，稍后再重试。
500服务器内部错误检查服务端日志和数据库连接。

注意：code 是 JSON 响应中的业务代码，不一定与 HTTP 状态码相同。请先安全解析响应，再检查业务代码；HTTP 429 等传输层状态码应单独记录。
